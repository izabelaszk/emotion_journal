> **Portfolio project** — end-to-end NLP/speech pipeline built as an extension of my master's thesis:  
> *"Applying Quantitative and Qualitative Methods to the Analysis of Emotions in Texts"*  

Speak or type a journal entry → emotions are detected → you hear personalised audio feedback.  
Every entry is stored and the session can be summarised in natural language via a local LLM.

## Pipeline

```
🎤 Voice / ⌨️ Text
        │
        ▼
 [Whisper STT]           ← openai/whisper-base  (GPU-accelerated)
        │ transcription
        ▼
 [Emotion Classifier]    ← DistilRoBERTa (transformer)  |  Ollama llama3.2 (zero-shot)
        │ joy · sadness · anger · fear · surprise · disgust · neutral
        ▼
 [gTTS Speaker]          ← personalised audio feedback
        │
        ▼
 📓 SQLite Journal  →  Gradio UI  +  FastAPI REST API
```

---

## Architecture

| Component | Technology | Notes |
|---|---|---|
| STT | `openai/whisper-base` | swappable model size |
| Emotion classifier | `j-hartmann/emotion-english-distilroberta-base` | public pretrained checkpoint; swap for your own |
| LLM zero-shot classifier | Ollama `llama3.2` (local) | optional, mirrors thesis methodology |
| TTS feedback | `gTTS` | Google Text-to-Speech |
| Demo UI | `Gradio` | dark-themed, microphone + upload |
| REST API | `FastAPI` | Swagger docs at `/docs` |
| Storage | `SQLite` | persisted via Docker volume |
| Containerisation | `Docker` + `docker-compose` | one-command GPU deploy |

## Quickstart

### Docker (recommended)

```bash
git clone https://github.com/izabelaszk/emotion_journal
cd emotion_journal

docker compose up --build
```

- Gradio UI → http://localhost:7860  
- API docs  → http://localhost:8000/docs


### Local Python

```bash
# Install GPU PyTorch first so Whisper builds against it, then the rest.
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121
pip install -r requirements.txt

# Gradio UI
python app.py

# FastAPI
python api.py
```

## Classifier backends

```python
from src.emotion_classifier import EmotionClassifier

clf = EmotionClassifier(backend="transformer")   # pretrained DistilRoBERTa, j-hartmann (primary)
clf = EmotionClassifier(backend="ollama")         # zero-shot via local Ollama
clf = EmotionClassifier(backend="nrc")            # lexicon baseline, no GPU needed

scores = clf.predict("This is absolutely wonderful news!")
# [{"label": "joy", "score": 0.91}, ...]
```

The NRC backend needs TextBlob's corpora once: `python -m textblob.download_corpora lite`.

## Evaluation

Backends benchmarked on 1,000 single-label examples from the
[GoEmotions](https://huggingface.co/datasets/google-research-datasets/go_emotions) test split,
mapped to Ekman-6 + neutral with the official GoEmotions → Ekman mapping (seed 42, CPU only):

| Backend | Accuracy | Macro-F1 | Latency mean (ms) | Latency p95 (ms) |
|---|---|---|---|---|
| transformer (DistilRoBERTa) | 0.449 | 0.401 | 17.0 | 21.8 |
| nrc (lexicon) | 0.355 | 0.151 | 0.5 | 1.2 |
| *majority class (always "neutral")* | *0.373* | *0.078* | – | – |
| ollama (llama3.2, zero-shot) | not yet run | – | – | – |

Notes:
- **Macro-F1 is the headline metric.** The sample is 37% neutral and only ~2% each fear and disgust,
  so accuracy rewards predicting "neutral"; macro-F1 weights every emotion equally.
- **The transformer score is optimistic:** the j-hartmann checkpoint was trained partly on GoEmotions,
  so this is not a clean held-out test for it. NRC and the Ollama LLM are true zero-shot baselines.
- Latency is per request on a laptop CPU (Intel Core i7-11800H), excluding model load.

Reproduce (writes `results/eval.json`):

```bash
python -m scripts.evaluate                                  # transformer + nrc
python -m scripts.evaluate --backends ollama --n 200        # needs `ollama serve`
```

## Product thinking

**Who it's for:** people who keep a journal and want to see how their mood changes over time,
without tagging every entry by hand. Speaking is faster than typing, and the spoken reply closes the loop.

**What I'd measure:**
- *Agreement rate*: how often users accept the detected emotion versus correcting it. This is the most direct
  signal of model quality in real use, and it's more relevant than any benchmark.
- *Retention*: whether people come back to journal on day 7 and day 30.
- *Latency*: time from the end of a recording to the spoken feedback. Users notice anything above a few seconds.

**What I'd build next:**
1. A "that's not how I feel" button that stores corrections, giving a labelled dataset for fine-tuning
   on real journal text instead of Reddit comments.
2. Mood trends over weeks, rather than one summary per session.
3. Multilingual entries (Whisper already transcribes Polish; the classifier doesn't handle it yet).

## Development

```bash
# Lint (config in ruff.toml)
ruff check .

# Fast, offline unit tests — no model downloads, GPU, or network
pytest -m "not integration"

# Full suite, including model-backed integration tests
pytest
```

Tests are split into a fast offline layer (`tests/test_unit.py` — pure logic,
SQLite journal, TTS templating) and slower `@pytest.mark.integration` tests that
load the real models. The heavy imports are deferred so `-m "not integration"`
never triggers a model download during collection.
